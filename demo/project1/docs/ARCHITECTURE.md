# Архитектура

## Обзор

Приложение разделено на три независимых слоя, связанных только через события:

```
┌────────────────────────────────────────────────────────────┐
│  React UI (меню, HUD, оверлеи, диалоги)                    │
│  подписка: store.events, engine.events, l10n.events        │
├────────────────────────────────────────────────────────────┤
│  GameEngine (systems/) — игровой цикл, системы, пулы       │
│  ThreeRenderer (engine/)  — отрисовка, instancing, LOD     │
│  InputManager (input/)    — клавиатура/сенсор/мышь         │
│  AudioEngine (audio/)     — процедурный WebAudio           │
├────────────────────────────────────────────────────────────┤
│  GameStore (core/GameState) — единое состояние + сейвы     │
│  LevelGenerator (world/) — детерминированные уровни        │
│  Gates / Economy (чистые функции, покрыты тестами)        │
└────────────────────────────────────────────────────────────┘
```

React не участвует в игровом цикле: GameEngine живёт в собственном
`requestAnimationFrame` и шлёт HUD-снапшоты ~10 раз/сек.

## Паттерны

### 1. Компонентно-ориентированный подход (лёгкий ECS)
Сущности уровня — плоские объекты с компонентами, взятые из пулов:

- `ObstacleEntity {x, z, w, d, kind, damage, persistent, cooldown}`
- `GateEntity`, `CoinEntity`, `BonusEntity`, `MeteorEntity`

Системы (обновляются строго по порядку в `GameEngine.update`):
`Formation → Events → Gates → Collisions → Bonuses → Wall → Finish`.
Разделение на системы позволяет тестировать каждую логику независимо
(см. чистые функции `world/Gates.ts`).

### 2. Observer / EventEmitter
Типизированная шина `EventEmitter<M>` используется везде:

- `store.events` — изменение состояния (UI перерисовывается);
- `engine.events` — `hud | complete | fail | pause | banner | state`;
- `l10n.events` — смена языка.

Хендлеры изолированы try/catch: сбой одного подписчика не роняет игру.

### 3. Object Pool
`ObjectPool<T>` для препятствий (переиспользуются между перезапусками уровней
и минами босса), частиц рендерера — кольцевой буфер без аллокаций.
В игровом цикле **нет** `new`, `push` (кроме редких событийных путей),
строковой конкатенации и создания Map — всё переиспользуется.

### 4. Управление состоянием
`GameStore` — единственный источник правды (`SaveData`):
прогресс, монеты, улучшения, бусты, настройки, статистика, сюжетные флаги.
Мутации только через методы (`completeLevel`, `buyUpgrade`, `setSettings`…),
каждая мутация → `commit()` → автосохранение (дебаунс 350 мс) + событие `change`.

### 5. Сериализация и миграции
`SaveManager` хранит JSON в `localStorage` (ключ `crowd-rush-save-v3`).
`migrateSave()` глубоко сливает сохранение с дефолтами, фильтрует невалидные
значения; повреждённый JSON → дефолт без исключений. `MemoryStorage` —
замена для тестов.

## Рендер (ThreeRenderer)

| Объект | Техника | Draw calls |
|---|---|---|
| Толпа (≤200) | `InstancedMesh` + `setColorAt` | 1 |
| Препятствия (7 видов) | `InstancedMesh` на вид | 7 |
| Ворота (арки) | 2 × `InstancedMesh` (пилоны/перекладины) × 2 цвета | 4 |
| Вывески ворот | `Sprite` с canvas-текстурой (кэш по символу) | ≤ 20 |
| Монеты / бонусы / метеоры | `InstancedMesh` | 3 |
| Частицы | `THREE.Points` (кольцевой буфер 400) | 1 |
| Стена босса + шипы + волна | Mesh + InstancedMesh + Torus | 3 |
| Окружение | купол-градиент, земля, борта, декор-здания | ~6 |

Итого **≈ 25–45 draw calls** (лимит по ТЗ — 200).

**LOD** (`quality: auto|low|med|high`):
- low: pixelRatio ≤1, без теней, без спрайтов, без декора, половинные частицы;
- med: pixelRatio ≤1.5, тени 1024;
- high: pixelRatio ≤2, полные эффекты.
Автоопределение: мобильные/≤4 ядра → low.

## Процедурные ассеты

- **Текстуры** — canvas 2D: земля (сетка+акцент), стены боссов (кирпич+трещины),
  барьеры (полосы), ящики (доски), вывески ворот (символы ×2/+N…).
- **Уровни** — `Rng` (mulberry32, seed = номер уровня): сегменты
  «ворота → препятствия → монеты», события, босс-стены с атаками.
- **Аудио** — WebAudio: осцилляторы + шумовые буферы (SFX), процедурный
  музыкальный луп (бас-секвенсор 132 BPM), вибрация через `navigator.vibrate`.

## Поток игрового кадра

```
input.getSteer() → leaderX (lerp) → leaderZ += speed·dt
→ таймеры (щит/магнит/адреналин/заморозка)
→ очки = speed·dt·10·mult·(адреналин·бусты)
→ updateFormation (позиции в переиспользуемом Float32Array)
→ updateEvents (метеоры, ветер, монетный дождь)
→ updateGates (пересечение z-плоскости, выбор арки)
→ updateCollisions (бакеты z/4, танки-поглотители)
→ updateBonuses → updateWall (толкание, атаки босса)
→ renderer.updateCrowd / update / render
→ emitHud (10 Гц, только при изменениях)
```

## Ключевые файлы

|---|---|
| `src/game/systems/GameEngine.ts` | игровой цикл, 8 систем, HUD-эмиссия |
| `src/game/engine/ThreeRenderer.ts` | WebGL, instancing, LOD, частицы |

| `src/game/core/SaveManager.ts` | localStorage, миграции, автосохранение |
| `src/game/localization/LocalizationManager.ts` | JSON-словари, смена языка на лету |
| `src/ui/GameScreen.tsx` | мост движок ↔ React (оверлеи, диалоги) |
